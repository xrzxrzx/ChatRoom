# 编码规范

> 适用范围：ChatRoom 项目全部代码（C++ / Go / C# / SQL / 协议文档）。
> 版本：v1.0 | 更新日期：2026-08-15

## 一、通用原则

1. **可读性优先**：命名要自解释，避免缩写（业界通用缩写除外，如 `id`、`msg`）。
2. **文档驱动**：接口与协议先行，代码与 `docs/` 保持一致（见 [项目开发规范](../AGENTS.md) 工作流）。
3. **小步提交**：每个阶段/功能一个提交，提交信息遵循 [Git 提交规范](#六git-提交规范)。
4. **不破坏构建**：任何提交前必须通过对应语言的构建与测试。
5. **中文注释**：项目以中文注释为主，代码标识符一律使用英文。

## 二、C++（ChatRoom.Server）

### 命名

| 类别 | 约定 | 示例 |
| ---- | ---- | ---- |
| 类 / 结构体 / 枚举 | PascalCase | `ChatServerService`、`ServerConfig` |
| 函数 / 成员函数 | PascalCase | `HandleLogin`、`BroadcastRoomListUpdate` |
| 成员变量 | camelCase | `chatRoomMap`、`nextRoomId` |
| 局部变量 / 参数 | camelCase | `roomId`、`session` |
| 常量 / 宏 | 大写 + 下划线 | `MAX_MESSAGE_LENGTH` |
| 头文件保护 | `#pragma once` | |
| 文件命名 | 与类名一致 | `ChatServerService.h/.cpp` |

### 规范要点

- 统一 C++20（`stdcpp20`），优先使用标准库容器与智能指针。
- **禁止裸 `new`/`delete`**；资源管理使用 RAII（`shared_ptr`、`unique_ptr`、Asio 对象）。
- 异步回调中**不得持有裸 `this` 穿越对象生命周期**；需要延后回调时捕获 `shared_from_this()` 或采用"关闭标记 + 延迟移除"模式（参考 `UserSession::Close` 与 `RequestRemoveSession`）。
- 单线程事件循环（Boost.Asio io_context）内不额外加锁；跨线程共享数据才需要同步。
- 日志统一使用 spdlog，禁止 `printf`/`std::cout` 直接输出业务日志；中文日志字符串使用 UTF-8（源文件带 BOM）。
- 魔法数字抽为具名常量或配置（见 `ServerConfig`）。
- `using namespace std;` 仅允许在 .cpp 内、且以 `using std::xxx;` 精确引入。

### 格式

- 缩进：Tab；大括号：Allman 风格（`{` 独占一行）。
- 头文件内联小函数允许单行实现。

## 三、Go（ChatRoom.Server.Models）

### 命名

| 类别 | 约定 | 示例 |
| ---- | ---- | ---- |
| 包名 | 小写单词 | `database`、`jwt` |
| 导出标识符 | PascalCase | `GenerateToken` |
| 未导出标识符 | camelCase | `jwtSecret` |
| 结构体字段 | 按导出规则 | `UserId`、`SessionToken` |

### 规范要点

- **必须通过 `gofmt`**（提交前 `gofmt -l .` 应为空）。
- 错误处理：不吞错误；`log.Fatal` 仅用于启动阶段，业务错误返回 `error`。
- 包级 `init()` 不做有外部依赖的初始化（如数据库连接），显式调用优于隐式初始化。
- gRPC 服务方法返回 `(Resp, error)`，业务失败也返回非 nil error 并在响应中带错误信息。

## 四、C#（ChatRoom.Client / ChatRoom.Client.Core）

### 命名

| 类别 | 约定 | 示例 |
| ---- | ---- | ---- |
| 类型 / 方法 / 属性 | PascalCase | `ChatClientService`、`CallAPIAsync` |
| 私有字段 | `_` + camelCase | `_coreService` |
| 局部变量 | camelCase | `sessionToken` |
| 接口 | `I` 前缀 | `IChatClientService` |

### 规范要点

- 目标框架 .NET 10，启用 `Nullable` 与 `ImplicitUsings`。
- **`Dispose` 必须实现**，禁止 `throw new NotImplementedException()` 占位。
- `async` 方法以 `Async` 后缀命名；事件回调内避免 `async void`（UI 事件除外）。
- 依赖注入通过构造函数注入，禁止服务定位器滥用。
- 序列化统一使用 Newtonsoft.Json（协议层），JSON 字段保持 `snake_case`。

## 五、SQL 与协议

- 表名、字段名使用 `snake_case`：`user`、`session_token`、`user_id`。
- JSON 协议字段统一 `snake_case`（`post_type`、`room_info_list`）。
- 数据库字符集使用 `utf8mb4`；所有 DDL 提供可重复执行的初始化脚本（`CREATE TABLE IF NOT EXISTS`）。

## 六、Git 提交规范

- 格式：`<scope>：<摘要>`，如 `Stage 2：服务端稳定性完善（...）`。
- 摘要用中文，控制在 50 字以内；必要内容写入正文。
- 一个提交只做一件事：文档提交、代码提交、测试提交可分离。
- 提交前确保：构建通过、相关测试通过、文档已同步。
