# API

客户端 → 服务端请求/响应协议。

## 概览

- 传输：TCP（服务端默认端口 `12345`，可通过 `server.json` 配置）
- 编码：UTF-8
- 消息边界：每条 JSON 以换行符 `\n` 结尾（兼容 `\r\n`）
- 方向：客户端 → 服务端（服务端 → 客户端事件见 [Event](event.md)）

> **版本说明**：本文档描述当前协议。标注 📋 的接口/字段为规划中内容（对应 `docs/plans/` 中的阶段），实现后移除标记。

## 基本格式（请求）

```json
{
  "action": "命令",
  "params": {
    "key1": "value1",
    "key2": "value2"
  },
  "token": "令牌",
  "echo": "回声"
}
```

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| action | `string` | 命令名（见下表） |
| params | `object` | 命令参数；无参数时为空对象 |
| token | `string` | 会话令牌（JWT），由 login/register 返回；未登录时为空字符串 |
| echo | `string` | 回声，每次请求必须唯一，用于匹配响应 |

## 基本格式（响应）

```json
{
  "recode": 0,
  "message": "",
  "data": {
    "key1": "value1"
  },
  "echo": "回声"
}
```

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| recode | `int32` | 状态码，0 表示成功（见错误码表） |
| message | `string` | 错误消息，成功时为空 |
| data | `object` | 返回数据，出错时为空对象 |
| echo | `string` | 与请求一致的回声 |

### echo 约定

每个未关闭的请求都应使用唯一 echo，客户端据此将响应与请求匹配；服务端原样返回。

## 错误码（recode）

| recode | 含义 |
| ---- | ---- |
| 0 | 成功 |
| 1 | 通用业务错误（登录失败、注册失败等） |
| 400 | 参数非法（如房间名为空或超长、消息超长、JSON 格式错误） |
| 401 | 未登录/未授权 |
| 403 | 未加入聊天室（发送消息前需先加入房间） |
| 404 | 未知 API 操作，或房间不存在 |
| 409 | 房间名已存在 |
| 502 | 令牌不合法（缺失/伪造/过期） |

## 关于 action 字段

| 值 | 注解 |
| ---- | ---- |
| [register](#register) | 注册 |
| [login](#login) | 登录 |
| [logout](#logout) | 注销 |
| [create_room](#create_room) | 创建房间 |
| [get_room_list](#get_room_list) | 获取房间列表 |
| [join_room](#join_room) | 加入房间 |
| [send_message](#send_message) | 发送消息 |
| [heartbeat](#heartbeat) | 心跳回应 |
| [request](#request预留) | 请求（预留） |

> **登录/注册时机**：login/register 仅允许在连接建立后的第一条消息发送；登录成功后服务端才开始处理后续 API。

## register

**请求参数**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| password | `string` | 密码（建议 ≥6 位） |
| nickname | `string` | 昵称 |

**返回数据**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| user_id | `int32` | 用户 ID（服务端分配） |
| session_token | `string` | 会话令牌（JWT） |
| nickname | `string` | 用户昵称 |

**说明**

- 注册成功后即返回会话令牌，客户端应保存并在后续 API 中携带。
- 用户 ID 由服务端分配，请求中**不需要**（也不应）提交 user_id。
- 昵称唯一（📋 Stage 4 增加唯一索引），重复昵称返回错误。

## login

**请求参数**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| user_id | `int32` | 用户 ID |
| password | `string` | 密码 |

**返回数据**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| user_id | `int32` | 用户 ID |
| session_token | `string` | 会话令牌（JWT） |
| nickname | `string` | 用户昵称 |

**说明**

- 登录成功后，后续所有 API 调用必须携带返回的 `session_token`。
- 身份以 token 声明为准，登录失败返回 `recode=1`。

## logout

**请求参数**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| session_token | `string` | 会话令牌（身份由 token 决定） |

**返回数据**

无

**说明**

- 注销成功后服务端关闭该连接。
- 注销后该 token 失效（📋 Stage 4 黑名单机制）。

## create_room

**请求参数**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| room_name | `string` | 房间名：非空、≤32 字符、不可与现有房间重名 |

**返回数据**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| room_id | `int32` | 新房间 ID |
| room_name | `string` | 房间名 |

**错误码**

| recode | 场景 |
| ---- | ---- |
| 400 | 房间名为空或超长 |
| 409 | 房间名已存在 |

**说明**

- 创建成功后，创建者**自动加入**该房间。
- 用户创建的房间在最后一名成员离开后自动关闭并从房间列表移除。
- 系统默认房间（服务端启动时创建的初始房间）常驻，不会自动关闭。

## join_room

**请求参数**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| room_id | `int32` | 房间 ID |

**返回数据**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| success | `bool` | 是否成功加入房间 |

**说明**

- 加入成功后服务端广播 `notice(join_room)`；房间人数变化通过 `update(room_list)` 通知。
- 已在其他房间时，加入新房间会自动离开原房间。

## send_message

**请求参数**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| message | `string` | 发送的消息（≤配置的最大长度，默认 4096 字符） |

**返回数据**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| message | `string` | 发送的消息 |

**说明**

- 仅允许已加入房间的用户发送；未加入返回 `recode=403`。
- 身份由 token 决定，不需要 `sender` 参数。
- 服务端向房间内**其他成员**广播 `message` 事件，**不含发送者本人**；本人消息通过本次响应回显，客户端不应依赖事件避免重复显示。

---

## heartbeat

**请求参数**

无

**返回数据**

| 字段 | 类型 | 注解 |
| ---- | ---- | ---- |
| time | `int64` | 服务端时间戳 |

**说明**

- 服务端定期下发 `heartbeat` 事件（见 [Event](event.md#heartbeat)），客户端收到后应回发本接口。
- 服务端根据客户端活跃状态清理死连接（超过 idle 超时无数据则断开）。
