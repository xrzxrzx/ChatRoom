# Stage 4 实施方案：安全与配置加固

## 一、目标

消除当前代码中明文密码、硬编码 JWT 密钥与数据库连接串的安全隐患，并提供可复现的数据库初始化能力。

## 二、当前状态

1. `User.go` 明文存密码、明文比对。
2. `JWTManager.go` 密钥硬编码 `your-secret-key-change-this`。
3. `DatabaseConnection.go` DSN 硬编码 `root:612278@tcp(127.0.0.1:3306)/chat_service`。
4. 无建库建表脚本；昵称无唯一约束。
5. `Logout` 不真正注销 token。

## 三、方案细节

### 3.1 密码哈希

- 引入 `golang.org/x/crypto/bcrypt`。
- `CreateUser` 入库前 `bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost)`；User 结构体 `Password` 字段语义改为"密码哈希"。
- `GetUserById` 后由调用方 `bcrypt.CompareHashAndPassword` 比对；登录 RPC 返回统一"用户ID或密码错误"。

### 3.2 配置化

`config.yaml` 扩展：

```yaml
port: 50051
jwt_secret: "change-me-in-production"
db:
  host: 127.0.0.1
  port: 3306
  user: root
  password: ""
  database: chat_service
```

`Database.InitDB` 改为接收配置；`JWT` 包提供 `SetSecret`。

### 3.3 数据库初始化

`docs/sql/init.sql`：

```sql
CREATE DATABASE IF NOT EXISTS chat_service DEFAULT CHARACTER SET utf8mb4;
USE chat_service;
CREATE TABLE IF NOT EXISTS `user` (
  `id` INT AUTO_INCREMENT PRIMARY KEY,
  `password` VARCHAR(255) NOT NULL,
  `nickname` VARCHAR(64) NOT NULL,
  UNIQUE KEY `uk_nickname` (`nickname`)
);
```

### 3.4 注销黑名单

- `JWT`/会话层维护 `sync.Map` 黑名单（token → 注销时间）。
- `Logout` 校验 token 有效后加入黑名单；`ValidateSession`/`GetSessionInfo` 先查黑名单。
- 注释说明：内存实现重启失效，生产可替换 Redis。

### 3.5 注册重复昵称

注册时先按昵称查询（或依赖唯一索引返回 1062），失败返回"昵称已被占用"。

## 四、技术选型

- `golang.org/x/crypto/bcrypt`：成熟、无 CGO 依赖（`bcrypt` 包纯 Go）。
- 黑名单：`sync.Map`，零依赖。

## 五、接口/数据设计

无协议字段变更；错误语义对齐：

| 场景 | 返回 |
| ---- | ---- |
| 昵称重复注册 | `success=false`，错误信息"昵称已被占用" |
| 登出 | `success=true`；旧 token 之后校验失败 |

- 新增 `docs/sql/init.sql`。
- 部署说明（README/CI 环境变量）。

## 七、测试策略

- `JWT`：密钥配置、黑名单校验用例。
- `User`：哈希创建/比对用例（sqlmock）。
- 手工：init.sql 初始化后注册登录全流程。

## 八、验收标准

- 数据库中无明文密码；登录可用。
- 重复昵称注册被拒。
- 登出后旧 token 校验失败。
- 配置文件中密钥/DSN 生效。

## 九、风险与回滚

- 风险：已存在明文数据的库无法直接登录（需重新注册或迁移哈希）。
- 应对：文档标注"新部署用 init.sql；老库需迁移"。
- 回滚：bcrypt 改动可回退到明文（不推荐），配置化带默认值保证可启动。
