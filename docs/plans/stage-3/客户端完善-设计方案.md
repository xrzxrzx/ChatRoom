# Stage 3 实施方案：客户端健壮性完善

## 一、目标

修复客户端"收不到他人消息、发送人 ID 恒 0、Dispose 抛异常、断线无感知"等问题，并补齐事件类型支持。

## 二、当前状态

1. `ChatClientEventBus` 按 `typeof(T).Name` 订阅、按 `post_type` 派发，键不匹配导致事件无法送达（B4）。
2. `ChatRoomFunction.OutputMessage` 解析字段错误（B6）。
3. 多个 `Dispose` 抛 `NotImplementedException`（B7）。
4. 重连仅置登录态为 false，无自动重连与恢复（B14）。

## 三、方案细节

### 3.1 事件总线键统一

订阅改为以 `post_type` 为键：

```csharp
public void Subscribe<T>(Action<T> handler) where T : EventMessageBag
{
    string key = GetPostType(typeof(T)); // "MessageEvent" -> "message"
    ...
}
```

方案 A：约定 `T` 类名去掉 `Event` 后缀并转小写；方案 B：给事件类型加 `PostType` 特性。采用 **方案 A**（改动最小，当前事件类名与 post_type 一一对应）。

### 3.2 消息发送者解析

```csharp
var id = @event.Data.Value<int?>("sender") ?? 0;
```

### 3.3 Dispose 实现

- `ChatClientAPIService.Dispose`：取消所有未完成等待项。
- `ChatClientEventService.Dispose`：关闭事件通道，清空订阅。
- `ChatClientCoreService` 已有 Dispose；`ChatClientService` 委托给内部服务。
- `ChatRoomService.Dispose`：取消订阅、断开连接。
- `App` 退出时（`OnLaunched` 注册退出钩子/主窗口关闭）调用 `Dispose`。

### 3.4 自动重连

- 接收循环 `finally` 中区分"主动断开"与"意外断开"。
- 意外断开时启动重连任务：按配置重试连接；成功后若持有 token 则重新发送登录（或调用 `ValidateSession` 后恢复）；失败则触发 `OnLoginStatusChanged` 提示用户。
- 重连期间 UI 显示"连接中断，正在重连…"。

### 3.5 新事件处理

- `UpdateEvent`：`update_type == room_list` 时更新房间人数。
- `NoticeEvent`：`join_room`/`leave_room` 输出系统消息。
- `HeartbeatEvent`：回发心跳请求。

### 3.6 UI 交互

- `MessageTextBox.KeyDown` 回车触发发送。
- `ChatListView` 新消息时 `ScrollIntoView(最后一项)`。
- 登录窗口关闭后恢复主窗口（已有逻辑，补充异常保护）。

### 3.7 创建房间 UI（新增需求）

#### 交互

- 房间列表区域顶部增加"创建房间"按钮（登录后可用）。
- 点击后弹出 `ContentDialog` 输入房间名（≤32 字符，前端先做非空/长度校验）。
- 确认后调用 `create_room` API：
  - 成功：刷新房间列表（服务端已自动将创建者加入新房间），并选中新房间；
  - 失败（400/409）：在对话框中展示服务端错误消息。

#### 房间列表动态刷新

- 收到 `update(room_list)` 事件时，以服务端全量列表替换 `RoomInfoList`，覆盖房间新增、移除与人数变化。
- 若当前选中的房间已被移除（被关闭），自动取消选中并清空消息区，提示"房间已关闭"。

## 四、技术选型

- 保持 CommunityToolkit.Mvvm + WinUI 3 不变；事件分发仍用 Channel 异步队列。
- 自动重连复用现有 `ConnectAsync` 重试逻辑，抽出公共重试方法。

## 五、接口/数据设计

无协议变更；客户端新增对 `update`、`heartbeat`、`notice(leave_room)` 事件类型的处理（与 Stage 2 服务端配套）。

## 六、影响范围

- `ChatRoom.Client.Core`：`ChatClientEventService.cs`、`ChatClientAPIService.cs`、`ChatClientService.cs`。
- `ChatRoom.Client`：`ChatRoomService.cs`、`ChatRoomFunction.cs`、`MainWindowViewModel.cs`、`MainWindow.xaml(.cs)`、`App.xaml.cs`。
- 文档：`docs/event.md` 客户端行为说明。

## 七、测试策略

- Core 单元测试：事件总线订阅/发布/退订；`MessageBagAnalysis` 事件/响应识别；`OutputMessageInfo` 转换。
- 集成验证：双客户端收发、房间人数更新、断网重连、正常退出。

## 八、验收标准

- 他人消息实时显示且发送人 ID/昵称正确；本人消息不重复。
- 断网后自动重连并恢复登录态（或明确提示）。
- 关闭应用无异常。

## 九、风险与回滚

- 风险：事件总线键约定在新增事件类型时可能失效。
- 应对：方案 A 配套单元测试锁定；必要时升级方案 B（特性标注）。
- 回滚：客户端改动不影响服务端，可独立回退。
