# Stage 5 实施方案：文档与工程化

## 一、目标

让项目具备清晰的入口文档、与实现一致的协议文档，以及可持续的自动化检查能力。

## 二、当前状态

- 无根 README；构建与运行步骤只存在于个人记忆。
- `docs/api.md` 存在 `actino` 拼写错误、字段缺失；`docs/event.md` 描述了未实现的 heartbeat/update。
- `.github` 仅有 copilot-instructions，无 CI。
- `Compile Protos.bat` 为 GBK 编码，中文提示乱码。

## 三、方案细节

### 3.1 根 README

包含：
- 项目简介与架构（Mermaid 图：Client ↔ C++ Server ↔ Go gRPC ↔ MySQL）。
- 目录结构说明。
- 环境要求与版本（.NET 10.0.400、VS 工具集 v145、vcpkg 于 `E:\App\vcpkg`、Go 1.24+、MySQL 8）。
- 快速开始：`init.sql` → `go run` → C++ 启动 → 客户端启动。
- 配置说明（`ChatClient.yaml`、`config.yaml`、`server.json`）。
- 已知限制与后续路线。

### 3.2 协议文档对齐

以代码为准逐接口核对：

| 接口 | api.md 修正点 |
| ---- | ------------- |
| send_message | `action` 字段名纠正 |
| get_room_list | 返回 room_info_list 含 user_count |
| join_room | 说明修正为"加入聊天室" |
| register | 参数移除 user_id，返回 user_id |
| login | 返回补 user_id |
| logout | 参数改为 session_token（Stage 1 后） |
| create_room | 新增：请求 room_name，返回 room_id/room_name，错误码 400/409 |

`event.md` 同步 Stage 2 新增的 heartbeat/update/leave_room，并明确 `update(room_list)` 为全量列表（覆盖新增/移除/人数变化）。同时在 `message` 事件一节补充说明：**服务端广播不含发送者本人，本人消息由 API 响应回显**（对应 Stage 2 的发送者过滤逻辑，避免客户端重复显示）。

### 3.3 CI

`.github/workflows/ci.yml`：

```yaml
jobs:
  go:
    - checkout + setup-go
    - cd ChatRoom.Server.Models && go test ./...
  dotnet:
    - setup-dotnet 10.0.x
    - dotnet build ChatRoom.Client.Core
  cpp:
    - windows-latest, 安装 vcpkg 依赖后 MSBuild ChatRoom.Server（best-effort）
```

### 3.4 protoc 脚本

将 `Compile Protos.bat` 转存为 UTF-8（含中文提示），插件路径支持环境变量覆盖：

```bat
set grpc_plugin=%VCPKG_ROOT%\installed\x64-windows\tools\grpc\grpc_cpp_plugin.exe
if not defined VCPKG_ROOT set VCPKG_ROOT=E:\App\vcpkg
```
